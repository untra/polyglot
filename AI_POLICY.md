# AI Policy

Using AI (i.e., LLMs) as tools for programming is welcome. This project itself encourages and lends itself to AI assisted language translations.
Still, A high bar is held for software development process used by humans and AI to develop all contributions to this project.
Moreover, the project maintainers remain responsible for any code that is published as part of a software release.
Code Contributors to this project are expected to be responsible for what they publish.

Individuals, Companies, and even Governments rely on this software, and so we hold our work to a high standard, considering both security and quality of our code contributions.

**AI should not be used to generate comments when communicating with maintainers.**

Comments are expected to be written by humans. Comments that are believed to be written by AI may be hidden without notice.

If you are opening an issue, you should be able to describe the problem in your own words.

If you are opening a pull request, you are expected to be able to explain the proposed changes in your own words. This includes the pull request body and responses to questions.

**Do not copy + paste responses from the AI when replying to questions from maintainers.**

The endeavor of this project is to help humans build better multi-language websites using the jekyll library.

AI assisted document translation and coordination can assist with communication and accreditation of websites built with this library.

Not all LLMs are at exceptional levels of support for language translation and software development; tests and human validation are important.

**Contributions made by autonomous agents may be closed, perhaps without notice, and will be prioritized appropriately.**

AI has accelerated the pace of software development and bug discovery.

This project is a self-documenting build tool. It will release and update at a pace most comfortable for collective software maintenance and development.

Contributions made by humans, benefiting other humans, will be prioritized over contributions made by robots, for other robots.

**Contributions made by autonomous agents may only be considered if the work can be attributed to a human or organization.**

Many individuals, businesses, organizations and even governments rely on this software.

A supply chain attack is a technique by which hackers make malicious injections into the development process of software. This technique allows hackers to cause problems for downstream consumers of affected executables. This is a concern for open source software projects at the moment.

Tracing the origin of contributed and consumed software libraries may likely soon be expected of OSS as a testament to its quality and security provenance. This is compromised when vendors and contributors cannot be ascertained. Therefore this project cannot accept purely anonymous contributions; all contributions must come from named human software developers.

**AI is a tool, so lets use it responsibly. It can really help make software development better.**

If you wish to include context from an interaction with AI in your comments, it should be in a quote block (e.g., using `>`) and disclosed as such.
It must be accompanied by human commentary explaining the relevance and implications of the context. Do not share long snippets of AI output.

AI is useful when communicating as a non-native English speaker.
If you are using AI to edit your comments for this purpose, please take the time to ensure it reflects your own voice and ideas.
If using AI for translation, we recommend writing in your native language and including the AI translation in a separate quote block.
